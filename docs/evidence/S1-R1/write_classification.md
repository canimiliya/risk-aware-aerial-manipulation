# write 1200 秒诊断分类

结论：`WRITE_CPU_RUNTIME_TOO_SLOW`。人话：程序没有崩，而是一直占用 CPU、cost 持续变化，1200 秒仍未完成并发布双轨迹，因此判为 CPU 太慢。

## 证据

- 1200 秒内收到轨迹：`False`；捕获退出码：`2`。
- JPS 搜索段数：`7`，JPS 用时：`1.502` 秒。
- MINCO 开始阶段最接近可见时间戳：`1785504751.1745083`；原始 Begin 行没有独立 ROS 时间戳；优化完成日志：`False`。
- cost：样本 `7563`，首个 `6.20901e+17`，最小 `14938000.0`，最后 `14938000.0`。
- CPU 峰值 `1937.0`%，RSS 峰值 `689736` KB；快照 `[60, 300, 600, 900, 1200]`。
- 日志未见 abort、segmentation fault、NaN 或 Inf。

## 不能过度解读的地方

这次证据能确认 CPU 持续计算且未在时限内完成；它不能证明换成更快硬件后一定能收敛，也没有修改任何官方参数来尝试。

原始标签：`SUBMITTED_S1_R1_WRITE_RUNTIME_TOO_SLOW`（提交给复核，表示 write 诊断完成但 write 本身未通过）。
